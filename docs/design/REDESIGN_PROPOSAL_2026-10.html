FFrontrow redesign
Frontrow · design proposal · October 2026

One look for the whole app

Today each screen has its own header, its own colours and its own tiny typewriter labels. This proposal gives every screen the same frame, the same type and the same colour rules, so the app feels like one product. It changes how things look and where a few things live. It does not remove features, and no database changes are needed.

Section 1 · Approach

Why redesign

The app grew feature by feature, and each feature brought its own styling. I counted what's in the code today on main:

1,552text sizes set to 11px or smaller, below the comfortable reading floor
1,216labels in the typewriter (mono) font, even where nothing is a number
430ALL-CAPS labels that slow reading down
370emoji used as icons, which render differently on every phone
4,497one-off inline styles, so the same thing looks different on each screen
6 + 2header styles, plus two competing styling systems

Section 1 · Approach

The decisions we agreed

You picked Direction 2 (Consolidate) and accepted these recommendations. They set the frame for everything else.

1 · Navigation

Desktop: a slim top bar (Home, Clubhouse, Trophies, Bets, Coins). Mobile: the same five in a bottom bar.
Why: one place to go home from anywhere, and thumbs reach the bottom of a phone.

2 · Light headers

Headers are white cards. Navy is kept for two places only: the Frontrow front page and your trophy profile.
Why: navy everywhere made every screen feel the same weight; saving it makes those two feel special.

3 · Quiet sport colour

Football, F1 and tennis colours appear only as a 4px marker on the crest or tile.
Why: sport colour was clashing with action blue and state green/red.

4 · Dark mode

Built into the colour tokens in Wave 0, switched on for users after Wave 2.
Why: costs almost nothing if done at the start, and every later screen gets it for free.

5 · Brand voice

Archivo Black for titles, the Frontrow newspaper as the signature, tabular numbers everywhere; mono only for scores, prices and countdowns.
Why: keeps the sports-paper character without the typewriter clutter.

6 · Crests are mandatory

Every player shows their club crest: pitch, lists, market, live, recap, sheets.
Why: you flagged this as a deal breaker. It's how people recognise players at a glance.

Two families. Archivo is a sturdy, slightly condensed grotesque made for headlines and sports data; its Archivo Black cut gives the newspaper-masthead feel. JetBrains Mono stays, but only where digits must line up in a ticking value.

Rules

12px floor

Nothing smaller than 12px. Body text is 15–16px with a 1.5 line height.

Sentence case

"Transfer window open", not "TRANSFER WINDOW OPEN". Capitals only for codes like GK, DEF, ARS.

Tabular numbers

All points, ranks and prices use tabular figures so columns line up without needing mono.

Section 1 · Approach

Colour

A warm paper background with ink text, one action colour and three state colours. Every colour is a token with a light and a dark value, so dark mode is a switch rather than a rebuild. Contrast is calculated live below; everything passes WCAG AA (4.5 : 1) for text.

Blue = action

Buttons, links, selected tabs. If it's blue, you can press it.

Gold = rank

Leader, podium, trophies, captain.

Green / red = state

Window open, wins, injuries, penalties.

Sport = marker

A 4px stripe on the crest or tile. Never a background.

TokenUsed forLightContrastDarkContrast

Side menu plus panel. Commissioner console and app admin.

Slides up on phones, centred dialog on desktop. Player stats, manager squad, compare.

Section 1 · Approach

Risks and how we handle them

The site is live

Small PRs per wave, a rollback tag before each merge, and checks at 375 / 768 / 1280px in light and dark before shipping.

Build-order crashes

The bundler (Rolldown) crashes when one module is imported at two depths. New shared components get imported in one place only, and every PR runs a production build.

Crest coverage

A few clubs (Chelsea, Newcastle, Spurs) are missing from the club logos. A neat monogram fallback shows until the logo is added.

Visual regressions

No automated screenshot tests yet, so I review each changed screen in the browser and send you before/after shots.

No database work

This is front-end only. No migrations, no SQL, no function deploys.
