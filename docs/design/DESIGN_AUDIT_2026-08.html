Design & accessibility assessment

Frontrow
Design Report

The system is sound. The product doesn't use it.

Frontrow ships a well-built token layer and a small set of correct primitives. Across 112 view files there are 4,127 inline style objects, and the canonical Select component is imported by none of them. Everything below follows from that gap — including a sign-in screen whose input fields are currently invisible.

22 August 2026 · live pass added 23 August 2026 Commit 1f4e937 21 findings · 7 critical WCAG 2.1 AA
Section one

What was found

Three findings are critical, meaning a user meets them on the way in and cannot work around them. Four are high, four medium, three low. None of them is a matter of taste — every one is a measured number or a count against the repository.

3
Critical. Contrast and visibility failures on the sign-in path and across all secondary text.
4
High. Structural: unused primitives, no type ramp, unfinished migration, missing focus states.
4
Medium. Touch targets, mismatched chip colours, radius sprawl, navigation coverage.
3
Low. Inline font declarations, stale animation colours, mixed radii inside one component.

The thesis

Fixing the sign-in screen, the four failing button states and the position chips takes about a day. It also fixes nothing structurally. With 4,127 inline style objects and a primitive layer nobody imports, the next screen anyone builds will drift the same way — because hand-writing styles is currently the path of least resistance and the design system is the detour. The work worth committing to is the lint rule and the conversion habit, because those are what stop the gap widening again.

Update — live verification, 23 August 2026

The counts above are the original source-review pass. A live pass across eight signed-in screens (see Method & limits) added findings 15–21: four more critical and three more high, all real contrast failures a browser rendered, not source-derived estimates. Three of the four new critical items sit in global chrome — the bottom nav's active tab colour and the header's "Beta" badge — so in practical exposure they rank above several of the original fourteen. Detail in the full ledger.

Section five · Findings 4, 6, 10, 12 · The root cause

The system exists.
Nothing uses it.

Navigation reaches a third of the product

The router serves 35 routes. The three sport navs expose 11 destinations between them — football five, F1 five, tennis three. Twenty-four routes are reachable only by direct URL. That is an information-architecture question rather than a bug, but it is worth answering deliberately: either those screens matter and should be navigable, or they don't and should go.

Section six

Method & limits

How this was assessed

Live inspection of the deployed sign-in screen — computed styles and DOM at 375px and 1280px — plus a full read of the token layer, the primitive components and all 112 view files at commit 1f4e937. Every contrast figure was computed from the shipped token values under the WCAG 2.1 relative-luminance formula; every count is a repository count, not an estimate.

What is not covered

Updated 2026-08-23 — signed-in screens have now been exercised live (see below) via the app's local demo-mode flag, which grants a session with no credentials. The one gap that remains: the demo account has no seeded league or clubhouse, so squad-builder, league-standings, draft and trade flows with real data are still unverified against live rendering — only their leagueless empty states are confirmed.

Live verification pass — 2026-08-23

Eight signed-in routes exercised directly in the browser under local demo mode (Trophy Cabinet, Coin Wallet, Settings, Squad, League, Live, Market, Recap), each scanned with an automated WCAG contrast walk of every rendered text node against its true composited background (alpha-blended up the ancestor chain, not just the nearest opaque layer). All fourteen original findings hold up against live rendering — nothing they predicted turned out to be wrong. Seven further contrast failures surfaced that source review didn't catch, listed as 15–21 in the ledger below; three repeat identically across every screen because they sit in global chrome (the header badge and the bottom nav), so their exposure is wider than most of the original fourteen.

What held up well

The leagueless empty states — Squad, League, Live, Market, Recap, Trophy Cabinet — all render cleanly with sensible copy and clear calls to action; none crash or show a broken layout for a fresh account with zero data. Two background 401 requests fire on load under demo mode (queries that assume a real session); they're cosmetic and don't affect the UI.
