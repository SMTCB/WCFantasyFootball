Design Assessment · 22 August 2026
Frontrow
Platform Audit
Verdict
System sound,
adoption failing
Frontrow has a genuinely well-designed token layer and a small set of correctly-built primitives. The product almost never uses them. Across 112 view files there are 4,127 inline style objects, and the canonical Select component is imported by zero of them. The visible symptom is the Kit Light migration: dark-theme values survive in enough places that the sign-in screen currently ships with invisible input fields.

The five that matter most
01
The sign-in fields are invisible
Both inputs paint rgba(255,255,255,.04) on a white card, with a rgba(255,255,255,.1) border — a measured 1.00:1. Verified on the live deployment.
Critical
02
Every secondary label fails contrast
The muted token measures 2.69:1 on the page ground — and it carries nearly all metadata in the app, usually at 9–11px.
Critical
03
Hover states erase their own labels
Primary hover drops to 1.91:1 and gold to 1.63:1. Both hover colours are pre-migration dark-theme values.
Critical
04
The primitives exist; nobody imports them
Button: 5 of 112 files, against 447 hand-rolled buttons. TextInput: 1 file, 101 raw inputs. Select: 0 files, 30 raw selects.
High
05
Type has no ramp — 20 sizes, 122 set at 9px or smaller
Set three different ways — 92 inline objects, 355 Tailwind arbitraries, 27 CSS rules — with no named steps. 68% of all type sits below 12px.
High
Method
Live inspection of the deployed sign-in screen — computed styles and DOM at 375px and 1280px — plus a full read of the token layer, the primitive components and all 112 view files.
Not covered
Signed-in screens were read from source, not exercised live — entering credentials isn't something I can do. Findings there are code-verified rather than observed in use.
